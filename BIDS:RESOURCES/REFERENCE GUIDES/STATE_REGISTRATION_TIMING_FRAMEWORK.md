 # State Registration Timing Framework
 
 **Purpose:** Prevent unnecessary upfront foreign registration costs while staying compliant with solicitation requirements.
 
 **Last updated:** March 9, 2026
 
 ---
 
 ## Core Rule
 
 For each opportunity, classify state authorization requirements into one of three timing buckets:
 
 1. **At Bid Submission**
 2. **Prior to Award**
 3. **Prior to Contract Execution / Start**
 
 **Only register early when the solicitation explicitly requires registration at bid submission.**
 
 ---
 
 ## Decision Matrix
 
 | Requirement Timing | Recommended Action | Risk Level |
 |---|---|---|
 | At Bid Submission | Register now (or bid as subcontractor under registered prime) | High if skipped |
 | Prior to Award | Bid now; register immediately after Notice of Intent to Award | Medium if delayed |
 | Prior to Contract Execution/Start | Bid now; register after award, before kickoff | Low if tracked |
 | Not stated / ambiguous | Submit question to CO immediately; do not assume | Medium |
 
 ---
 
 ## Cost-Control Strategy
 
 ### Tier 1 - Register Now
 Use only if all are true:
 - Requirement is "at time of bid", OR portal prequalification blocks bidding
 - Win probability >= 35%
 - Projected annual DDI margin >= $50K
 
 ### Tier 2 - Register After Intent to Award
 Use when:
 - Requirement is "prior to award"
 - Bid allows non-registered firms at submission
 - Time to complete registration fits award window
 
 ### Tier 3 - Register After Award
 Use when:
 - Requirement is "prior to contract execution/start"
 - Registration not required for bid responsiveness
 
 ### Tier 4 - Subcontract Route
 Use when:
 - State registration is expensive/high burden (for example CA, TX)
 - Requirement is unclear or timing risk is high
 - Prime is already in-state authorized
 
 ---
 
 ## Mandatory Question for Every Out-of-State Opportunity
 
 Ask CO/procurement contact:
 
 "Is authorization to transact business in [State] required at bid submission, prior to award, or prior to contract execution?"
 
 Document the answer in `WORKFLOW_CHECKLIST.md` under compliance.
 
 ---
 
 ## Recommended Workflow Step (Add to Every Checklist)
 
 **STATE AUTHORIZATION GATE**
 - [ ] State identified
 - [ ] Requirement timing classified (bid / award / execution)
 - [ ] Registration decision made (now / after award / subcontract route)
 - [ ] CO clarification requested if requirement is ambiguous
 - [ ] Owner assigned + due date for registration action
 
 ---
 
 ## Current Pipeline - Timing Defaults (Until Solicitation Says Otherwise)
 
 | State | Default Approach |
 |---|---|
 | Illinois | Register now (IPG/portal gate requires it) |
 | Kentucky | Usually prior to award/contract; verify each RFP |
 | Georgia | Usually prior to award/contract; verify each ITB/RFP |
 | California | Prefer post-award unless bid explicitly requires pre-bid qualification |
 | Texas | Prefer post-award due high initial filing cost unless required earlier |
 | Ohio | Post-award unless bid states otherwise |
 | Pennsylvania | Post-award unless bid states otherwise |
 
 ---
 
 ## Red Flags - Register Early Anyway
 
 Register before bid submission if any red flag appears:
 - Solicitation says "must be authorized at time of submission"
 - Bid portal blocks submission without active state registration ID
 - Form requires SOS number as mandatory field with no exception path
 - Responsiveness checklist lists state authorization as required attachment
 
 ---
 
 ## Bottom Line
 
 **Do not pay multi-state registration costs upfront by default.**
 
 Register early only when required to be responsive. Otherwise, use a post-award timeline or subcontract route to protect cash while preserving bid access.
